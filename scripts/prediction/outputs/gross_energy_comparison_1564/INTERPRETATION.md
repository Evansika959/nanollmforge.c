# 不扣基线后的训练结果

沿用旧随机扫描的 1,564 个有效架构，训练 / 验证 / 测试为 1,100 / 150 / 314，三个训练种子。原始测量和划分不变，不加入温度、功率、批次或采集顺序等运行状态特征。按照数据核对流程，原始字段保持不变，新能耗标签单独保存。

新目标为 `total_energy_j × 1000 / 32`，包含 prefill、decode 以及推理测量窗口内的设备背景耗电。不是纯 decode 动态能耗。新总能耗模型重新训练，动态能耗对照使用原有检查点，已复现其 81 个测试指标。

## 主要结果

下表为三个种子的平均 MAPE，越低越好。比较的是两种不同物理目标各自的预测误差，不是相同标签上的算法提升。

| 模型 | 动态能耗（扣基线） | 总能耗（不扣基线） |
|---|---:|---:|
| XGBoost，14 特征 | 26.69% | 44.15% |
| XGBoost，32 物理特征 | 26.81% | 44.52% |
| 分组 Transformer，32 特征 | 26.90% | 43.41% |

不只是百分比误差变大：XGBoost14 的 MAE 从 6.12 增至 16.56 mJ/token，R² 从 0.795 降至 0.589，Spearman 从 0.887 降至 0.736。Transformer 的总能耗 MAPE 略低于两种 XGBoost，但并非所有指标都更好，也不构成明显实用优势。

XGBoost14 总能耗学习曲线：训练 598 / 849 / 1,100 个架构时，合并测试集 MAPE 为 41.22% / 42.77% / 44.15%。新批次测试改善（37.03% → 34.40%），旧批次测试恶化（44.03% → 50.69%）。添加的数据来自另一个采集批次，不能把这条曲线解释为纯粹的样本数量效应。

## 为什么与 v2 重复实验不同

旧随机扫描的背景功率差异明显：P10 为 79 mW，P90 为 301 mW。对 XGBoost14，测试架构上三种子平均的有符号 log 残差与实测基线功率的相关系数，总能耗为 −0.888，动态能耗为 −0.415。

| 测试集基线功率（仅事后诊断） | 架构数 | 总能耗预测 / 实测中位数 |
|---|---:|---:|
| <150 mW | 118 | 1.71 |
| 150–200 mW | 3 | 1.43 |
| ≥200 mW | 193 | 0.73 |

低背景功率架构普遍被高估，高背景功率架构普遍被低估。这与“仅由架构无法辨别采集时背景状态”的解释一致，但相关性不能证明具体原因是屏幕、无线通信或温度。功率和温度只用于事后解释，未加入预测器，也未据此删除样本或调参。

之前 v2 重复实验显示的是特定受控采集条件下、同架构的重复性；本实验检验的是旧随机采集条件下、未见架构的可预测性。两者不是同一个问题。取消基线扣除可以避免基线估计噪声，同时也保留了真实背景负载差异，这批旧数据中后者不能忽略。

## 后续使用

旧 1,564 个架构暂时保留动态能耗作为较可预测的标签，新总能耗模型保存为实验检查点，不自动替换搜索器。若目标确实是设备总能耗，下一步应检验统一采集状态下的 v2 数据，并按架构分组划分，避免同一架构的不同重复同时进入训练和测试。50 个代表架构的重复可帮助判断测量噪声，但不能当作 250 个独立架构。

本次测试集此前已多次查看，结论为探索性。沿用旧清洗规则，包括动态能耗非正值与长耗时异常的排除，以保持成对比较公平，并未声称这是总能耗目标的最佳清洗规则。完整逐种子指标、预测和审计分别见 `summary.json`、`predictions.json`、`audit.json`、`diagnostics.json`。
